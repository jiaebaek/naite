# 14 · 성장 좌표 데이터 모델 — 과학·탐구 풀 예시 (전략 산출물)

> **용도.** SSOT §5-B(성장 좌표) 데이터 모델을 **한 영역으로 끝까지** 설계해 포맷을 확정한다. 이 형식이 확정되면 나머지 6영역으로 확장.
> **원칙(어기면 안 됨):** [00-전략-원칙.md](00-전략-원칙.md) §5-B.
> - 부모 화면 = **서술**("요즘 이런 모습"). **단계 숫자/level 부모 비노출**(내부 ordinal만).
> - ⛔ 또래 비교·"정상/지연"·나이 도달선 금지. 나이 = "이 시기엔 이런 모습을 **볼 수 있어요**"(관찰 메뉴).
> - 좌표 = **아이 고유 모양**(기질·관심). 좋고 나쁜 모양·완성형 없음.
> - 덜 보이는 모습 = 결핍 아니라 **다음 경험**.
> - 관찰행동은 `자체·근거표기`(누리 연결) · "가볍게 체크, 진단 아님"(겸손).
> - 기존 데이터(묶음·활동·커버리지) 위에 **상태 레이어를 얹는다**(갈아엎기 X).

---

## 1. 데이터 타입 (초안)

```ts
type GrowthPoint = {
  id: string
  domain: Domain
  name: string            // 부모 언어. "탐구하는 태도"
  blurb: string           // 왜 중요한지 한 줄(부모 언어)
  behaviors: ObservableBehavior[]   // 완만한 연속선 순서(내부 ordinal = index)
  sourceRefs: string[]    // 근거(누리/성취기준 id) — 뒤에
}

type ObservableBehavior = {
  id: string
  order: number           // 0..n 내부 ordinal (부모 비노출)
  parentText: string      // "궁금한 걸 물어봐요" — 체크 문항
  sourceRef: string       // 이 행동이 연결된 기준 id
}

// 부모가 남기는 근거. 여러 소스가 같은 behavior 를 켤 수 있다.
type Evidence = {
  growthPointId: string
  behaviorId: string
  source: 'parent_observation' | 'activity' | 'academy' | 'achievement'
  at: IsoDate
}

// 좌표 = Evidence 로 계산(저장 안 함). 부모에겐 label 만 보인다.
type GrowthState = {
  growthPointId: string
  observedOrder: number   // 켜진 behavior 중 최고 order (내부)
  parentLabel: string     // 서술. "궁금하면 직접 알아봐요"
  isStrength: boolean     // 이 아이 프로필에서 상대적으로 앞선 곳(강점 발견용)
}

type NextExperience = {
  growthPointId: string
  fromOrder: number       // 이 좌표 다음에 제안
  parentText: string      // "다음엔 이런 모습을 볼 수 있어요"
  activityId?: string     // 연결 활동(Pull · 무료·집 먼저)
}
```

> **핵심:** GrowthState 는 **계산값**(Evidence→최고 order→label). 저장 안 하니 근거가 바뀌면 좌표도 바뀐다(성장 반영). `observedOrder`·숫자는 **내부 전용**, 부모는 `parentLabel`만 본다.

## 2. GrowthPoint #1 · 탐구하는 태도 (풀 설계)

```
id: sci-inquiry
domain: 과학·탐구
name: "탐구하는 태도"
blurb: "궁금한 걸 알아가는 힘 — 이 시기엔 '왜?'가 자라는 게 중요해요."
sourceRefs: [nuri-nat-1, nuri-nat-2, nuri-nat-3]
```

**관찰 가능한 행동** (완만한 연속선 · 부모 체크 예/아직/모름):

| order | parentText (체크 문항) | 근거 |
|---|---|---|
| 1 | 새로운 것·자연을 보면 관심 있게 봐요 | nuri-nat-1 |
| 2 | "왜?"·"이건 뭐야?" 궁금한 걸 물어봐요 | nuri-nat-1 |
| 3 | 궁금하면 직접 만져보고 살펴봐요 | nuri-nat-2 |
| 4 | 한 방법이 안 되면 다른 방법도 해봐요 | nuri-nat-2 |
| 5 | 발견한 걸 이야기하거나 다른 사람 생각도 궁금해해요 | nuri-nat-3 |

**좌표 → 부모 서술(parentLabel)** (켜진 최고 order 기준):

| observedOrder | parentLabel (부모가 보는 것) |
|---|---|
| 0 | "이 모습은 아직 덜 보여요 — 같이 해보면 나타나요" (결핍 아님·초대) |
| 1 | "새로운 것에 관심을 보이는 모습이 보여요" |
| 2 | "궁금한 걸 물어보는 모습이 보여요" |
| 3 | "궁금하면 직접 알아보는 모습이 보여요" |
| 4 | "여러 방법으로 알아보는 모습이 보여요" |
| 5 | "발견을 나누고 다른 생각에도 관심 갖는 모습이 보여요" |

**다음 경험(NextExperience):**

| fromOrder | parentText | 연결 활동 |
|---|---|---|
| 0~1 | "다음엔 '왜?'를 같이 궁금해하는 모습을 볼 수 있어요" | act-sci-1 (산책하며 "이건 왜 그럴까?") |
| 2~3 | "다음엔 여러 방법으로 알아보는 모습을 볼 수 있어요" | act-sci-4 (물에 뜰까 가라앉을까 먼저 맞혀보고 확인) |
| 4~5 | "충분히 잘 자라고 있어요 — 급하지 않아요" | (제안 없음 · 원칙3) |

> 근거는 **뒤에**: 부모가 "왜 이 목표?" 탭하면 `nuri-nat-1~3` 원문 노출("전문가가 세운 국가 기준").

## 3. GrowthPoint #2 · 사물·도구 탐색

```
id: sci-things · sourceRefs: [nuri-nat-4, nuri-nat-10]
name: "사물·도구 살펴보기" · blurb: "물건이 어떻게 되고 도구가 어떻게 움직이는지 알아가요."
```
| order | 행동 | 근거 |
|---|---|---|
| 1 | 물건의 다른 점(크기·무게·촉감)을 알아차려요 | nuri-nat-4 |
| 2 | 물건이 어떻게 되는지(섞이나·뜨나) 해보고 봐요 | nuri-nat-4 |
| 3 | 가위·집게·자석 같은 도구에 관심 가져요 | nuri-nat-10 |
| 4 | 도구를 직접 써보려고 해요 | nuri-nat-10 |

- 서술 예: 0="아직 덜 보여요" / 2="직접 해보며 살펴봐요" / 4="도구를 스스로 써봐요"
- 다음 경험: act-sci-5(가위·집게 어떻게 움직이나 함께 살펴보기)

## 4. GrowthPoint #3 · 자연·생명

```
id: sci-nature · sourceRefs: [nuri-nat-11, nuri-nat-12, nuri-nat-13]
name: "자연·생명 느끼기" · blurb: "동식물·날씨·계절을 관심 있게 보고 아껴요."
```
| order | 행동 | 근거 |
|---|---|---|

| 3 | 날씨·계절 변화를 알아차리고 말해요("추워졌어") | nuri-nat-13 |
| 4 | 날씨에 맞춰 뭘 할지 연결해요("비 오니 우산") | nuri-nat-13 |

- 다음 경험: act-sci-6(개미·꽃 관찰) · act-sci-9(창밖 날씨 → 옷 정하기)

## 5. 영역 화면 렌더 (과학·탐구 = 3 GrowthPoint 프로필)

부모가 보는 것 — **점수가 아니라 이 아이의 지형(고유 모양):**

```
🔬 과학·탐구 — 요즘 우리 아이 모습

🟢 탐구하는 태도    궁금하면 직접 알아봐요
🟢 자연·생명        동식물에 관심이 많아요
🟡 사물·도구        이 모습은 아직 덜 보여요

  이 아이만의 모양이에요 · 좋고 나쁜 모양은 없어요

다음에 한번 볼까요?
  물에 여러 물건 넣기 전에 "뜰까 가라앉을까?" 먼저 맞혀보고 확인 · 5분
  [이런 경험 해보기]
```

- 🟢 = 이 아이 프로필에서 **앞선 곳(강점) 먼저 보여줌** → "저 분야는 잘 가고 있네" 안도(§5-B 원리①).
- 🟡 = 결핍/경보 아님. "덜 보여요 → 다음 경험." 허니·빨강 금지.
- **또래 없음·숫자 없음·완성 없음.** "이 아이만의 모양."
- 재방문 시: 맨 위 "지난번보다 — 🟢 사물·도구도 이제 보여요" 델타(리텐션).

## 6. 좌표 계산 규칙 (결정적 · AI 아님)

1. behavior 켜짐 = Evidence 존재(부모 체크 / 활동 연결 / 학원 등원 / 이룸 중 하나라도).
2. `observedOrder` = 켜진 behavior 중 **최고 order**.
3. `parentLabel` = 그 order의 서술 템플릿(§2~4).
4. `isStrength` = 이 아이의 **영역 내 상대 비교**(GrowthPoint 간)에서 상위 → 🟢로 먼저 노출. **또래 아님, 자기 자신 내부.**
5. 다음 경험 = `fromOrder` 매칭(없으면 "급하지 않아요", 제안 안 함).

> ⚠️ observedOrder를 "5세면 4 이상" 식으로 판정 금지. 나이는 관찰 메뉴만 정하고, 도달 판정 안 함.

---

## 7. 기존 데이터와의 관계 (갈아엎기 X)
- **GrowthPoint ← 기존 묶음(cluster).** 과학·탐구 3묶음(inquiry/things/nature) = 3 GrowthPoint. 그대로 매핑.
- **관찰행동 ← 개별 성취기준(원문)을 부모 언어로 번안** + sourceRef로 원문 연결.
- **Evidence ← 기존 활동/커버리지/이룸** + **부모 관찰(신규, §06-B 체크 확장).**
- 커버리지 "챙기는 중"(활동 있음)은 유지하되, **좌표(모습)는 Evidence 종합**으로 별도 계산.

- [x] 덜 보임 = 다음 경험(결핍 아님)
- [x] "고유 모양·좋고 나쁨 없음" 명시
- [x] 관찰행동 근거표기(누리 연결), "가볍게 체크"
