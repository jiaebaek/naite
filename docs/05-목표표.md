# 목표 표 (Discovery 산출물 ①)

> 한 장으로 고정한다. 이후 모든 결정은 이 표와 충돌하지 않아야 한다.

| 항목 | 내용 |
|---|---|
| **제품 한 줄** | 공교육 기준을 좌표축 삼아 우리 집이 정한 속도로 **오늘 뭘 해야 하는지 한 화면에** 보여주는 모바일 웹앱 |
| **주 사용자** | 엄마 1명 (워킹맘 · 유일한 입력자 · 개발자) |
| **핵심 상황** | 평일 낮 회사에서 **조회·판단**, 저녁·주말에 **실행·체크** |
| **이길 대상** | 노션이 아니라 **냉장고에 붙인 A4 한 장 + 머릿속 기억** |

## 세 가지 핵심 판단

1. **오프셋**: 목표 시기 = 공교육 기준 시기 − 선행 오프셋(영역별). 현재 국어 12 / 수학 12 / 나머지 0 / 영어 N/A
2. **성격**: 활동은 겨냥하는 목표로부터 `필수` / `자체목표` / `자유` 로 **자동 분류**된다. **못 했을 때의 의미가 다르므로 UI도 달라야 한다**
3. **커버리지**: 영역별 `아직아님` / `비어있음` / `하는중` / `연결필요` / `기준밖` 를 표시한다. **빈 영역 발견이 이 시스템을 만드는 이유다**

## 개발 방식

- **DbC + TDD**. 요구사항 → 계약(INV-* / E-*) → 스켈레톤 → ARRR 사이클
- **ARRR** = RED → GREEN → Refactor → Repeat
- **ECB**: Entity 트랙 / Boundary 트랙 두 갈래로 진행
