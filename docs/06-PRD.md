## 4. 핵심 개념 모델

> **계약(INV-* / E-*)의 기반. 용어를 여기서 고정한다.**

### 4.1 Child
`생년월 = 2021-01` / `입학예정 = 2028-03`
파생: 현재 만 나이, **입학까지 남은 개월 수**

### 4.2 Domain (영역) — 교육과정 원문을 빠짐없이 덮는다

`국어` · `수학` · `과학·탐구` · `영어` · `사회·인성` · `예체능` · `건강·안전`

| 영역 | 누리과정 (취학 전) | 초1~2 (2022 개정) | 공교육 기준 | 선행 의미 |
|---|---|---|---|---|
| 국어 | 의사소통 | 국어 | 있음 | 있음 |
| 수학 | 자연탐구 · 생활 속에서 탐구하기 | 수학 | 있음 | 있음 |
| **과학·탐구** | 자연탐구 · 탐구과정 즐기기 / 자연과 더불어 살기 | 슬기로운 생활 | 있음 | **무의미** |
| **영어** | — | — (초3부터) | **없음** | 성립 안 함 → **자체 기준** |
| **사회·인성** | 사회관계 | 바른 생활 | 있음 | **무의미** |
| 예체능 | 예술경험 / 신체운동·건강(신체활동) | 즐거운 생활 | 있음 | **무의미** |
| **건강·안전** | 신체운동·건강(건강·안전) | 바른 생활(생활습관·안전) | 있음 | **무의미** |

영역마다 성질이 다르다. **균일하게 다루면 안 된다.**

> **초판은 5개(`국어/수학/영어/학교적응/예체능`)였고 누리과정 59개 중 19개(32%)만 덮었다.**
> `학교적응`은 교육과정 용어가 아닌 조어였다 — 정식 근거는 [2바01-01]과 누리과정 사회관계다.
> 전수 조사 경위: [원문/전수매핑.md](원문/전수매핑.md)
>
> **영역 목록이 원문을 덮지 못하면 P-6("모든 영역에서 다 하고 있는지")의 전제가 깨진다.**

### 4.3 Standard (공교육 기준 목표)
| 속성 | 설명 |
|---|---|
| domain | 소속 영역 |
| baselinePeriod | 공교육 기준 달성 시기 (`2027-09 ~ 2028-02`) |
| statement | **관찰 가능한 문장** ("받침 없는 단어를 소리 내어 읽는다") |
| source | 근거 (`누리과정 의사소통` / `2022개정 2국04-01`) |
| **origin** | **`공교육`(원문) \| `해석`(우리 판단) \| `자체`(우리가 세운 목표)** |

> `origin` 구분 필수. 04 문서의 🟦/🟨 구분이 유용했다는 피드백이 근거.
>
> **`자체` 추가 (사용자 결정 2026-08-21)**: *"기준이 없는 경우에는 자체적으로 기준을 설정할 수 있도록 하자."*
> → 영어처럼 공교육 기준이 없는 영역도 목표를 가질 수 있다.
> → 단 `자체` 기준에는 **오프셋을 적용하지 않는다** (이미 시기까지 우리가 정한 것이라 이중 조정이 된다).
> → **`자체`가 `공교육`으로 표시되어서는 안 된다.** 우리 판단이 국가 기준으로 둔갑하면 P-3를 앱 안에서 재생산한다.

### 4.4 PaceOffset (선행 오프셋) ⭐

```
우리 집 목표 시기 = Standard.baselinePeriod − PaceOffset(domain)
```

영역별로 따로 설정. 현재값: **국어 12 / 수학 12 / 영어 N/A / 과학·탐구·사회·인성·예체능·건강·안전 0** (개월)

**요구: 쉽게 변경 가능해야 한다** (사용자 명시)
→ 설정 깊이에 묻지 않는다. 영역 화면에서 **바로 조정**하고 **즉시 재계산**된다.

**안전장치 (필수)**
- 오프셋 상향 시 경고: *"오프셋은 목표 시기를 당길 뿐 발달 단계를 이기지 못합니다"*
- 회피·정체·짜증 신호 체크 항목 노출
- 없으면 이 앱은 **적기교육 도구가 아니라 선행 압박 도구**가 된다

### 4.5 Activity (활동)
| 속성 | 값 |
|---|---|
| name | `영어 원서 1권` |
| domain | 영역 |
| track | `학원` \| `집` |
| **targetIds** | **이 활동이 겨냥하는 Standard 목록. 0개 허용** ⭐ |
| cadence | `매일` \| `주N회` \| `요일지정` \| `비정기` |
| owner | `엄마` \| `아빠` — **표시 전용. 알림·요구 금지 (OOS-1)** |

**`nature`는 저장하지 않는다 — `targetIds`에서 파생된다** (2차 개정)

기존 설계는 `하는중`/`플러스`를 사용자가 직접 고르는 필드였다.
사용자 지적(*"플러스 의미가 뭔데? 플러스만 있으면 왜 보완필요야?"*)이 정확했다 —
`플러스`가 **①목표를 겨냥하지 않는다**와 **②못 해도 괜찮다**를 동시에 뜻했고,
자체 기준을 허용하면서 그 둘이 갈라졌다. (경위: [07-계약.md](07-계약.md) §2)

→ 사용자는 **"이 활동이 겨냥하는 목표"만 선택**(생략 가능)하고, 성격은 자동으로 나온다.

| 연결 상태 | 파생 nature | 못 했을 때 | UI 처리 |
|---|---|---|---|
| 공교육/해석 기준에 연결 | **`필수`** | 누적되면 문제 | 미완료를 명확히 표시 |
| 자체 기준에 연결 | **`자체목표`** | 조정 가능 | **중립 표시** |
| 연결 없음 | **`자유`** | **괜찮음** | **경고색 금지. streak으로 표현** |

> *"어제는 영상을 빼먹었어"* 는 **기준 위반이 아니다.**
> 그런데 지금은 한글 숙제 누락과 같은 무게로 느껴진다.
> **체크박스를 전부 똑같이 생기게 만들면 이 앱은 죄책감 생성기가 된다.**

### 4.6 DomainCoverage (영역 커버리지) ⭐ 신규 — P-6 대응

각 영역이 **지금 채워져 있는지**를 판정한다.

| 상태 | 목표 | 활동 | 겨냥 | 표시 의도 | 조치 |
|---|---|---|---|---|---|
| **`아직아님`** | 0 | 0 | — | **아직 시기가 아니다** | **없음. 빠뜨린 게 아니다** |
| **`비어있음`** | O | 0 | — | 시기인데 비었다. **발견이 목적** | 활동 추가 또는 "안 해도 됨" 판단 |
| **`기준밖`** | 0 | O | — | 왜 하는지 정리가 안 됨 | **자체 기준을 세우면 해소** |
| **`연결필요`** | O | O | ✗ | 하고는 있는데 목표는 안 덮인다 | 기존 활동을 목표에 연결 |
| **`하는중`** | O | O | ✓ | 그대로 두면 됨 | 없음 |

> **`아직아님` 추가 (사용자 지적)**: *"오프셋이 0이라서 지금 목표 시기가 아닌 거면 표시가 안 되는 거야?"*
> 4분류에서는 **아직 시기가 아닌 영역**과 **시기인데 빈 영역**이 둘 다 `비어있음`이었다.
> 전자는 정상 상태인데 "빠뜨렸다"로 읽힌다 → C-6 위반 / X-3.
> **이건 UI 문제가 아니라 도메인 판단이다.** 색을 칠하기 전에 이미 정해져 있다.

> **초안은 3분류였고 `플러스`만 있는 영역을 `비어있음`으로 판정했다.**
> 사용자 지적(*"플러스인데 왜 공백이야?"*)이 타당했다. 3분류가 **독립된 두 질문**
> (①뭔가 하고 있는가 ②목표를 덮는가)을 하나로 접어서, `플러스`만 있는 영역이 갈 칸이 없었다.
> → `연결필요`를 4번째 상태로 분리. 자세한 경위는 [07-계약.md](07-계약.md) §3.

> 용어 주의: `기준밖`(커버리지)와 `자유`(활동 성격)는 **다른 축**이다.
> - `자유` = 활동 하나의 성격 (겨냥하는 목표가 없음)
> - `기준밖` = 영역 전체의 상태 (영역에 목표 자체가 없음)

**판정 예시 (현재 상태)**

| 영역 | 활동 | 상태 |
|---|---|---|
| 국어 | 한글 학원 + 숙제 | `하는중` |
| 수학 | 팩토 + 알파짱 + 보드게임 | `하는중` |
| 영어 | 원서 + 영상 | `하는중` (자체 기준 수립 후) |
| 예체능 | 미술 + 체육 | `하는중` |
| **사회·인성** | **없음** | **`비어있음`** ⚠️ |
| **과학·탐구** | **없음** | **`비어있음`** ⚠️ |
| **건강·안전** | **없음** | **`비어있음`** ⚠️ |

> **이 표가 P-6의 답이다.** 04 문서가 지적한
> "초1 적응에서 실제로 가장 중요한데 아무도 안 챙기는 영역"이 시스템상으로도 비어 있다.
> 그리고 **영역을 5개에서 7개로 넓히자 숨어 있던 공백 둘이 더 드러났다.**
> 지금까지 몰랐던 이유는 **영역 단위로 조망한 적이 없고, 영역 목록 자체가 불완전했기 때문이다.**
>
> ⚠️ 위는 시드 데이터 기준이다. 실제 앱에서는 **사용자가 등록하는 대로** 판정된다.

### 4.7 Academy (학원)
`이름`/`영역`/`요일`/`시간`/`연락처`
현재: 더하다사고력(월 14:30) · 아이마음아트(수 14:30) · 유아체육(일 13:30)

### 4.8 Completion (수행 기록)
`날짜` + `activityId` + `완료여부`. 하루 1건. 메모는 선택.

### 4.9 ActionItem (처리할 일)
"미술학원에 시간 변경 문의" 같은 **숙제가 아닌 처리 항목**.
증거 D2. **평일 낮 회사에서 처리해야 하는 항목**이라는 점이 P-5와 직결.

### 4.10 Candidate (검토 중인 항목)
`찰리스 방과후영어` · `에그스쿨` · `일대일 방문영어`

`검토 사유` / **`판단 근거`** / `재검토 시점`

> 사용자 요청: *"고려중인 것들에 대한 해석이 좋았다. MVP까진 아니어도 후순위에 기록해달라."*
> **P-3 재발 방지 장치.** 등록 검토 시 *"누가 시작했다더라"* 가 아니라
> *"아이가 이 신호를 보인다"* 를 기록하게 강제한다. → **F7 / P2**

| F5 | **처리할 일** — 학원 연락 등. 평일 낮에 보이도록 | P-5 | P1 |
| F6 | **연속 기록** — `자유`·`자체목표`는 실패 표시 대신 streak | P-1 | P2 |
| F7 | **검토 중 항목** — 판단 근거·재검토 시점 기록 | P-3 | P2 |
| F8 | **주간 회고** — `필수` 항목 이행률만 요약 | P-2 | P2 |

> F3가 P-3와 P-6을 동시에 친다. **MVP의 중심은 F1이 아니라 F3다.**
> F1은 매일 열게 만드는 장치이고, F3는 이 앱을 만드는 이유다.

### F1 수용 기준 (계약 후보)
- 진입 후 **1회 탭 이내**에 오늘 할 일 전체가 보인다
- 오늘의 모든 영역이 **한 화면**에 들어간다
- 체크는 **탭 1회**로 기록된다 (확인 다이얼로그 없음)
- `자체목표`·`자유` 미완료는 **경고색으로 표시하지 않는다**
- 매번 로그인 화면이 뜨지 않는다

### F3 수용 기준 (계약 후보)
- 오프셋 변경 시 **"지금 우리 목표"가 즉시 재계산**된다
- 오프셋 조정이 **영역 화면에서 바로** 가능하다 (설정 메뉴에 묻지 않는다)
- 오프셋 상향 시 **발달 단계 경고**가 표시된다
- 각 목표에 🟦기준/🟨해석 구분과 **출처**가 표시된다
- 영어는 "공교육 기준 없음"으로 **명시적으로 다르게** 표시된다
- **활동이 0개인 영역은 `비어있음`으로 표시된다** ← P-6 핵심

MVP 배포(Pages) 후 실제로 사람들에게 보여주고 받은 피드백으로 UX를 재설계했다.

### 받은 피드백 → 대응

| # | 피드백 | 대응 | 판단 |
|---|---|---|---|
| ① ② | UX가 복잡·시스템 이해가 어렵다 | 상단 브랜드바 + 하단 3탭(오늘·영역·기록, 아이콘) + **관리는 ⚙로 강등**. 영역 카드 **접기**(눌러야 자세히) | 전면 수용 |
| ③ | 활동이 목표에 연결되는 구조인 줄 몰랐다 | 오늘·영역에 **연결 목표** 표시(`Task.targets`) | 수용 |
| ④ | 공교육 기준인지 모르겠다 | **출처 배지**(공교육·누리과정/성취기준 / 자체) — `provenanceOf` | 수용 |
| ⑤ | 커버리지를 그래프로 | **세그먼트 갭뷰** + 기록 **막대 그래프**. 단 **퍼센트·점수는 배제**(죄책감) | 의도 수용, 형태 조정 |
| ⑥ | '됨' 체크가 너무 쉽다 → 분리 | **'됨' 표시를 관리 탭 '성취 기록'으로 완전 분리.** 영역·오늘엔 됨 토글 없음 | 수용(강화) |
| ⑦ | 어제 한 활동을 기록 못 함 | 기록 탭 **지난 날 소급 기록**(펫 토큰은 안 줌) | 수용 |
| ⑧ | 기록을 리포트처럼 | 기록 탭 **주간 리포트**('한 것'만, 긍정 프레이밍) | 수용 |
| ➕ | "아직"이 애매 / 핵심가치 재확인 | 목표 상태 `활동필요`로 명명(=갭). **영역은 됨 숨기고 갭을 앞세워 "빈 곳"에 집중** | — |

### 핵심 가치 재정의 (사용자 명시)

> **나이 기준으로 꼭 챙겨야 할 것 중 빠뜨린(안 챙기는) 것을 찾아 메우는 것.**
> 달성이 목표가 아니라 챙기고는 있자 — *"앞서가진 않더라도 뒤쳐지진 말자."*

→ 영역 탭의 제1임무는 **갭(활동 필요) 발견**. '됨'은 끝난 것이라 그 뷰에선 숨긴다.
이는 P-6("어느 영역이 비어 있는지")의 직접 계승이다.

### 화면 구조 (현재)

| 화면 | 역할 |

| **영역** 🧭 (F3) | 갭 찾기 — 커버리지 세그먼트 + 목표별 상태(됨 숨김, 갭 우선) + 오프셋 |
