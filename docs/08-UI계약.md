## 회귀 방지 규칙 (2026-09 추가) ⚠️

기능을 고칠 때마다 옛 기능이 사라지던 문제가 있었다. 원인·재발방지:

1. **테스트가 깨지면 = 회귀 경보.** 기본 대응은 "코드를 고친다"이지 테스트가 아니다.
   테스트를 바꾸는 건 **사용자가 그 동작 변경을 명시 승인했을 때만**, 그리고 커밋과
   계약(INV-*)에 *왜 뒤집는지* 를 남긴다. (테스트를 통과시키려 고치면 그 계약은 죽는다.)
2. **사용자가 말한 동작은 즉시 잠금 테스트로 박는다** — 회귀 이력이 있는 계약엔 ⭐ 표시.
3. **커밋 전 테스트 diff 를 눈으로 검사** — "이 변경이 테스트를 *약하게* 만드나?"
4. 색·가시성처럼 jsdom 이 못 잡는 것은 **data 속성·요소 존재**로 단언 + 브라우저 확인.

> 계약에 없던 동작(테스트에만 있던 것)은 소리 없이 흘러간다 — 그래서 INV-UI-35/36,
> 세그먼트 3색, 오프셋 상시노출이 회귀했다. **동작은 반드시 이 문서에 계약으로 남긴다.**

## 0. 제1원칙 — UI 는 판단하지 않는다

도메인이 이미 판단을 내려놨다. UI 는 **그 결과를 표현만** 한다.

| 판단 | 소유자 | UI 가 하는 일 |
|---|---|---|
| 이 활동은 `필수`인가 `자유`인가 | `deriveNature()` | 받아서 표시 |
| **미완료를 경고할 것인가** | **`shouldWarnOnMiss()`** | **호출해서 그대로 따른다** |
| 이 영역은 `비어있음`인가 `아직아님`인가 | `evaluateCoverage()` | 받아서 표시 |
| 오프셋 상향 시 경고할 것인가 | `assessOffsetRaise()` | 반환값을 그대로 노출 |

> **UI 가 색을 자의적으로 정하면 C-6 가 언제든 깨진다.**
> "이건 중요해 보이니 빨갛게" 같은 판단이 컴포넌트에 들어가는 순간
> 도메인의 `shouldWarnOnMiss()` 는 장식이 된다.

| ID | 불변식 |
|---|---|
| **INV-UI-00** | 경고 여부는 **반드시 `shouldWarnOnMiss(nature)` 로 결정**한다. 컴포넌트가 `nature` 를 직접 비교하지 않는다 |

## 1. 화면 구성

**상단 브랜드바**(좌: 나이테, 우: ⚙관리) + **하단 탭 3개(오늘·영역·기록, 아이콘+라벨)**.
등록·설정 성격의 **활동(관리)은 하단 탭에서 빼 상단 우측 ⚙**로 옮겨 일상 복잡도를 낮춘다
(피드백 ①② "UX가 복잡·이해가 어렵다").

| 화면 | 기능 | 역할 |
|---|---|---|
| **오늘** 🌱 | F1 | 매일 열게 만드는 장치. 진입 기본 화면 |
| **영역** 🧭 | F3 | **이 앱을 만드는 이유.** 나이 기준 챙김 갭 찾기 + 오프셋 |
| **기록** 📖 | F4 | 지난 날 기록(소급) + 주간 리포트 |
| **관리(⚙)** | F2 | 활동·학원 등록·수정. 상단 우측 ⚙로 진입 |

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-01** | 앱 진입 시 **오늘 화면**이 바로 뜬다. 스플래시·온보딩·로그인 화면을 거치지 않는다 | C-5 (냉장고 종이는 0초) |
| **INV-UI-02** | 화면 계층은 **2단계를 넘지 않는다** (탭 → 상세) | C-3 |
| **INV-UI-03** | 매번 로그인 화면이 뜨지 않는다. 세션을 유지한다 | C-5 |
| **INV-UI-57** | **상단 브랜드바**에 나이테(좌)와 관리 진입 ⚙(우). 하단 탭은 **아이콘+라벨**. 관리는 하단 탭에 두지 않는다 | ①② + 프로토타입 셸 |

## 8. 3차 — UX 전문가 전면 리디자인 (2026-09)

프로토타입·명세([`../나이테_UX/`](../../나이테_UX/))를 **디자인 그대로** 구현했다.
§0 제1원칙(UI 는 판단하지 않는다)은 그대로 — 화면은 여전히 `evaluateCoverage()`·`goalStatusOf()`
가 준 상태만 표현한다. 바뀐 것은 **표현 방식과 정보 위계**다.

**색 토큰 확정** (§7 의 "미정" 해소): 프로토타입 CSS 를 `theme.css` 로 이식.
라이트+다크 둘 다 정의(`prefers-color-scheme` + `[data-theme]`). 역할 토큰만 쓴다 —
`--pine`(딥그린) · `--sage`(세이지) · `--honey`/`--honey-2`(꿀색=갭) · `--paper`/`--surface` · `--ink`.
갭은 **빨강이 아니라 꿀색**이다(원칙 4 · C-6/X-3 연장).

**화면 구성** (탭 3 + drill 2 + 온보딩):

| 화면 | 최상단 | 원칙 |
|---|---|---|
| 오늘 | **갭 배너** → 오늘 할 일(+등원) → 펫 | ①② — 매일 여는 화면이 곧바로 안심시키거나 채울 곳을 준다 |
| 영역 | 개요 → **갭 우선 정렬** 3그룹 | ① — `먼저 챙기면 좋아요`(비어있음) → `채우는 중`(연결필요/부분) → `다 챙기고 있어요` |
| 영역 상세 | 비어있는 목표 우선 + 추천 활동 | 목표별 [활동 연결]/[이미 해요] |
| 기록 | 나이테 링(채움률) + 주간 스트립 + 활동별 주간 목표 달성 | 한 것만 센다(C-6) — 스트립 탭 = backfill |
| 관리 | 아이 정보·학원·활동·성취 됨-처리 | `됨`/`됨으로` 토글, 활동으로 챙기는 목표는 자동 제외 |

**INV-UI-R1 — 선행 UI 없음(원칙 5).** 영역/상세 어디에도 `1년/2년 선행` 선택이 없다.
`currentTargets(standards, [], nowYm)` 로 오프셋 0(적기)만 계산한다. `pace.ts`/`gate.ts` 는
계약·테스트를 유지한 채 **휴면**한다(호출 안 함). ⭐ 회귀 방지: `AreaScreen`/`App` 테스트가
"선행" 문구 부재를 단언한다.

**INV-UI-R2 — 갭 우선.** 영역은 비어있는 곳이 항상 위로 온다. `App` 테스트가 DOM 순서를 잠근다.

**INV-UI-R3 — 이번 주 채운 주N회는 오늘에서 내린다.** `weeklyProgress.met && !done` 이면 숨긴다
(기존 INV-UI-36 계승). ⭐ `TodayScreen` 테스트로 잠금.

**INV-UI-R4 — 기록 탭 보강(Addendum 01, 2026-09).** 초안 단순화에서 빠졌던 두 기능을 되살렸다.

- **(A) 주간 목표 달성 표시.** 활동별 현황은 단순 횟수가 아니라 **목표 대비 달성**이다:
  `met`(완료·✓·세이지) / `0<done<target`(`N/M회`) / `done=0`("이번 주 없음"). 목표 칸 수만큼
  pip 를 두고 완료분만 세이지로 채운다. **미완 칸은 중립 회색** — 허니(갭색)를 쓰지 않는다
  (주간 미완은 갭이 아니라 진행 중, §04 혼동 방지). ⭐ `met` 은 도메인(`weeklyReport`)이 판정한다
  (INV-UI-00) — UI 가 `done>=target` 을 직접 비교하지 않는다.
- **(B) 지난 날 backfill.** 주간 스트립의 날짜(과거·오늘)를 탭하면 그 날 활동 체크시트가
  바텀시트(`DaySheet`, §10 과 동일 패턴)로 열린다. 토글 = 그 날짜 `Record` 추가/삭제.
  **미래 날짜는 비활성.** 오늘 체크와 **같은 Record 소스**라 스트립 도트·"N일 챙김"·주간 달성·
  나이테 채움률이 그 자리에서 일관 갱신된다. backfill 은 펫 토큰을 주지 않는다(펫=오늘의 리듬 전용).
- **카피(§14 연장).** 미완은 "실패"가 아니다 — "그냥 비어 있을 뿐이에요" / "지난 날도 채울 수 있어요".
  ⭐ `LogScreen`/`DaySheet`/`App` 테스트가 완료 어휘·미완 중립·미래 비활성·backfill 반영을 잠근다.

**INV-UI-R5 — 학원·활동 폼(§12 명세 보강).** 관리의 추가/편집은 **바텀시트 폼**(`ManageSheet`,
활동 연결·지난 날 시트와 동일 패턴)으로 연다. **추가/편집 한 컴포넌트 겸용** — 제목·초기값·삭제
버튼 유무만 분기.

- **활동 폼**: 이름 · **어디서(학원/자체/자유) 세그먼트** · (학원)소속 학원 select · 영역 칩 ·
  **주간 목표 횟수 스텝퍼(1~7)** · **겨냥 목표**(그 영역의 이 시기 목표 다중선택). 매핑:
  `학원`→track 학원+`academyId`, `자체`→track 집+겨냥 목표, `자유`→겨냥/스텝퍼 숨김·targetIds []·비정기.
  영역을 바꾸면 겨냥 목표를 초기화한다(계약: targetIds 는 활동 domain 과 같아야 함).
- **학원 폼**: 이름 · 등원 요일 · 등원 시간 · 연락처. (coversDomains 는 폼에 없어 `editAcademy` 가
  원본 값을 유지 — 편집이 등원 커버를 조용히 지우지 않게.)
- **저장/삭제**: 저장=`createActivity`/`editActivity`·`createAcademy`/`editAcademy`(도메인, id·active 보존).
  **삭제는 편집에서만** — 소프트 삭제(deactivate)이고, 라벨에 **위험색(--danger)** 을 쓰는 앱의
  유일한 자리(§05). ⭐ `ManageSheet`/`ManageScreen` 테스트가 매핑·분기·삭제 노출을 잠근다.
- ⚠️ **부수 수정**: `createActivity` 가 `input.academyId` 를 흘리던(누락) 버그를 고쳤다(INV-ACT-12) —
  폼의 '학원' 선택이 실제로 학원과 연결되도록. `activity.test` 가 잠근다.

**INV-UI-R6 — 2축 3상태(§04·§09·§12 개정).** 목표 상태는 **두 축**이다: **활동 연결(챙김)** 과
**됨(이룸)**. 이 둘을 "챙김" 하나로 뭉갠 초기 설계를 정정한다.

- **3상태 표시**: `goalStatusOf` 의 `활동필요`→**비어있음**(허니) · `챙기는중`→**챙기는 중**(연세이지) ·
  `됨`→**이룸**(세이지+체크). *도메인 값 이름은 그대로, 표시 라벨만 이 매핑을 따른다.*
- **영역 상세(3그룹)**: `채우면 좋아요(비어있음)` → `챙기는 중` → `이룸`. 요약 =
  `목표 {total}곳 · 이룸 {done} · 챙기는 중 {prog} · 비어있음 {gap}곳`(gap=0 → "비어있음 없음"),
  목표 단위 커버리지 pip 3색(`pip on`/`pip prog`/`pip gap`). 카드 액션:
  비어있음 **[활동 연결] [이뤘어요]** · 챙기는 중 **[이뤘어요]** · 이룸 **[이룸 해제]**(+부제
  `활동으로 이룸`/`직접 확인함`). `이뤘어요`·`이룸 해제` 는 같은 `MilestoneMark` 토글.
- **막다른 길 금지**: 이룸 해제 시 활동이 있으면 **챙기는 중**, 없으면 **비어있음**으로 되돌아간다
  — `goalStatusOf` 가 재계산하므로 토글이 사라지지 않는다.
- **관리 성취 됨-처리**: 됨은 활동 연결과 **무관하게 항상 토글 노출**(이전의 "활동으로 챙김" 태그로
  숨기던 것을 폐기). 활동으로 챙기는 목표는 `{활동}로 챙기는 중` 부제를 함께 보인다.
- 색: `--pip prog`/`--ms prog`/`--ms done`/`--ms2 tending`. ⭐ `DetailScreen`/`ManageScreen` 테스트가
  3상태·전이·라벨·부제를 잠근다.
