## 회귀 방지 규칙 (2026-09 추가) ⚠️

기능을 고칠 때마다 옛 기능이 사라지던 문제가 있었다. 원인·재발방지:

1. **테스트가 깨지면 = 회귀 경보.** 기본 대응은 "코드를 고친다"이지 테스트가 아니다.
   테스트를 바꾸는 건 **사용자가 그 동작 변경을 명시 승인했을 때만**, 그리고 커밋과
   계약(INV-*)에 *왜 뒤집는지* 를 남긴다. (테스트를 통과시키려 고치면 그 계약은 죽는다.)
2. **사용자가 말한 동작은 즉시 잠금 테스트로 박는다** — 회귀 이력이 있는 계약엔 ⭐ 표시.
3. **커밋 전 테스트 diff 를 눈으로 검사** — "이 변경이 테스트를 *약하게* 만드나?"
4. 색·가시성처럼 jsdom 이 못 잡는 것은 **data 속성·요소 존재**로 단언 + 브라우저 확인.

> 계약에 없던 동작(테스트에만 있던 것)은 소리 없이 흘러간다 — 그래서 INV-UI-35/36,
> 세그먼트 3색, 오프셋 상시노출이 회귀했다. **동작은 반드시 이 문서에 계약으로 남긴다.**

## 0. 제1원칙 — UI 는 판단하지 않는다

도메인이 이미 판단을 내려놨다. UI 는 **그 결과를 표현만** 한다.

| 판단 | 소유자 | UI 가 하는 일 |
|---|---|---|
| 이 활동은 `필수`인가 `자유`인가 | `deriveNature()` | 받아서 표시 |
| **미완료를 경고할 것인가** | **`shouldWarnOnMiss()`** | **호출해서 그대로 따른다** |
| 이 영역은 `비어있음`인가 `아직아님`인가 | `evaluateCoverage()` | 받아서 표시 |
| 오프셋 상향 시 경고할 것인가 | `assessOffsetRaise()` | 반환값을 그대로 노출 |

> **UI 가 색을 자의적으로 정하면 C-6 가 언제든 깨진다.**
> "이건 중요해 보이니 빨갛게" 같은 판단이 컴포넌트에 들어가는 순간
> 도메인의 `shouldWarnOnMiss()` 는 장식이 된다.

| ID | 불변식 |
|---|---|
| **INV-UI-00** | 경고 여부는 **반드시 `shouldWarnOnMiss(nature)` 로 결정**한다. 컴포넌트가 `nature` 를 직접 비교하지 않는다 |

## 1. 화면 구성

**상단 브랜드바**(좌: 나이테, 우: ⚙관리) + **하단 탭 3개(오늘·영역·기록, 아이콘+라벨)**.
등록·설정 성격의 **활동(관리)은 하단 탭에서 빼 상단 우측 ⚙**로 옮겨 일상 복잡도를 낮춘다
(피드백 ①② "UX가 복잡·이해가 어렵다").

| 화면 | 기능 | 역할 |
|---|---|---|
| **오늘** 🌱 | F1 | 매일 열게 만드는 장치. 진입 기본 화면 |
| **영역** 🧭 | F3 | **이 앱을 만드는 이유.** 나이 기준 챙김 갭 찾기 + 오프셋 |
| **기록** 📖 | F4 | 지난 날 기록(소급) + 주간 리포트 |
| **관리(⚙)** | F2 | 활동·학원 등록·수정. 상단 우측 ⚙로 진입 |

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-01** | 앱 진입 시 **오늘 화면**이 바로 뜬다. 스플래시·온보딩·로그인 화면을 거치지 않는다 | C-5 (냉장고 종이는 0초) |
| **INV-UI-02** | 화면 계층은 **2단계를 넘지 않는다** (탭 → 상세) | C-3 |
| **INV-UI-03** | 매번 로그인 화면이 뜨지 않는다. 세션을 유지한다 | C-5 |
| **INV-UI-57** | **상단 브랜드바**에 나이테(좌)와 관리 진입 ⚙(우). 하단 탭은 **아이콘+라벨**. 관리는 하단 탭에 두지 않는다 | ①② + 프로토타입 셸 |

## 6. 검증 방법 — 무엇이 자동이고 무엇이 수동인가

**정직하게 갈라둔다.** 전부 자동화되는 척하면 X-3 을 놓친다.

### 자동 (컴포넌트 테스트)

| 계약 | 검증 |
|---|---|
| INV-UI-00 / 11 | 컴포넌트 소스가 `nature ===` 로 직접 비교하지 않는다 (아키텍처 테스트) |
| INV-UI-05 | 할 일 없는 영역의 제목이 렌더되지 않는다 |
| INV-UI-06 / 07 | 체크 클릭 1회 → 상태 변경. 다이얼로그·입력 필드가 나타나지 않는다 |
| INV-UI-09 | `주N회` 활동에 진행 텍스트가 있다 |
| INV-UI-13 / 22 | 화면에 미완료 카운터·퍼센트 문자열이 없다 |
| INV-UI-14 | 영역 화면에 7개 영역이 모두 렌더된다 |
| INV-UI-16 | `자체` 배지와 `공교육` 배지의 클래스가 다르다 |
| INV-UI-18 | 오프셋 상향 시 경고와 신호가 렌더되고, 건너뛰기 버튼이 없다 |
| INV-UI-20 | `아직아님` 영역에 조치 버튼이 없다 |
| INV-UI-24 / 26 | 폼에 `nature` 입력과 알림 관련 컨트롤이 없다 |
| INV-UI-29 | 상태 요소에 텍스트 라벨이 함께 있다 |

### 수동 (실제 화면을 보고 확인)

| 계약 | 확인 방법 |
|---|---|
| **INV-UI-12** | 경고색이 빨강처럼 보이는가 |
| **INV-UI-21** | `기준밖` 가 "잘못됐다"로 읽히는가 |
| **X-2** (3초) | 앱 열고 체크까지 실제로 재본다 |
| **X-3** (죄책감) | **영어를 3일 빼먹은 상태의 화면을 보고, 기분이 나쁜가** |
| INV-UI-28 | 실제 폰에서 한 손으로 조작되는가 |

> **X-3 검증이 이 제품의 진짜 시험이다.**
> 기능이 다 맞아도 화면이 사람을 찌르면 2주 만에 안 열게 된다 (X-1).
> 배포 후 첫 주에 **일부러 며칠 빼먹은 상태로 화면을 열어보고** 판단할 것.
