## 0. 제1원칙 — UI 는 판단하지 않는다

도메인이 이미 판단을 내려놨다. UI 는 **그 결과를 표현만** 한다.

| 판단 | 소유자 | UI 가 하는 일 |
|---|---|---|
| 이 활동은 `필수`인가 `자유`인가 | `deriveNature()` | 받아서 표시 |
| **미완료를 경고할 것인가** | **`shouldWarnOnMiss()`** | **호출해서 그대로 따른다** |
| 이 영역은 `비어있음`인가 `아직아님`인가 | `evaluateCoverage()` | 받아서 표시 |
| 오프셋 상향 시 경고할 것인가 | `assessOffsetRaise()` | 반환값을 그대로 노출 |

> **UI 가 색을 자의적으로 정하면 C-6 가 언제든 깨진다.**
> "이건 중요해 보이니 빨갛게" 같은 판단이 컴포넌트에 들어가는 순간
> 도메인의 `shouldWarnOnMiss()` 는 장식이 된다.

| ID | 불변식 |
|---|---|
| **INV-UI-00** | 경고 여부는 **반드시 `shouldWarnOnMiss(nature)` 로 결정**한다. 컴포넌트가 `nature` 를 직접 비교하지 않는다 |

## 1. 화면 구성

MVP 는 화면 세 개다. **하단 탭 3개**, 그 이상 계층을 만들지 않는다.

| 화면 | 기능 | 역할 |
|---|---|---|
| **오늘** | F1 | 매일 열게 만드는 장치. 진입 기본 화면 |
| **영역** | F3 | **이 앱을 만드는 이유.** 커버리지 + 오프셋 |
| **활동** | F2 | 활동 등록·수정 |

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-01** | 앱 진입 시 **오늘 화면**이 바로 뜬다. 스플래시·온보딩·로그인 화면을 거치지 않는다 | C-5 (냉장고 종이는 0초) |
| **INV-UI-02** | 화면 계층은 **2단계를 넘지 않는다** (탭 → 상세) | C-3 |
| **INV-UI-03** | 매번 로그인 화면이 뜨지 않는다. 세션을 유지한다 | C-5 |

### 미완료 표현 — C-6 의 핵심

| nature | `shouldWarnOnMiss` | 미완료 표현 |
|---|---|---|
| `필수` | **true** | 활동명 옆 **점(•) 강조**. 색은 **앰버** |
| `자체목표` | false | **중립.** 빈 체크박스만 |
| `자유` | false | **중립.** 빈 체크박스만 |

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-11** | `shouldWarnOnMiss()` 가 false 인 항목에 **경고색·경고 아이콘·굵기 강조를 쓰지 않는다** | **C-6 / X-3** |
| **INV-UI-12** | 경고색으로 **빨강 계열을 쓰지 않는다.** 앰버까지만 | 빨강은 오류의 색이다. 아이가 숙제를 안 한 것은 오류가 아니다 |
| **INV-UI-13** | 미완료 개수를 **배지·카운터로 집계해 보여주지 않는다** | "3개 밀렸음"은 죄책감 장치다 |

> **X-3 은 "죄책감을 준다" 이다.** 기능이 아니라 감정이 판정 기준이라,
> 위 세 계약은 **화면을 직접 보고 확인**해야 한다 (§6 참조).

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-14** | **7개 영역 전부**가 이 화면에 있다. 필터로 숨기지 않는다 | **C-2 / P-6** |
| **INV-UI-15** | 각 목표에 **`origin` 표식과 출처**를 함께 보여준다 (🟦공교육 / 🟨해석 / 자체) | INV-STD-02 |
| **INV-UI-16** | `origin === '자체'` 를 **공교육처럼 보이게 하지 않는다** (같은 배지·같은 색 금지) | **INV-STD-05.** 우리 판단이 국가 기준으로 둔갑하면 P-3 재생산 |
| **INV-UI-17** | 오프셋 조정은 **이 화면에서 직접** 한다. 설정 메뉴로 이동시키지 않는다 | 사용자 요구: *"쉽게 변경 가능해야 해"* |
| **INV-UI-18** | 오프셋 **상향 시 `assessOffsetRaise()` 의 경고와 신호 목록을 모두 노출**한다. 건너뛰기 버튼을 두지 않는다 | **INV-PACE-05.** 없으면 선행 압박 도구가 된다 |
| **INV-UI-19** | 오프셋 변경 결과(`currentTargets`)를 **즉시 재계산해 같은 화면에서** 보여준다 | F3 수용 기준 |

### 커버리지 표현 — `아직아님` 와 `비어있음` 을 반드시 구분한다

| 상태 | 톤 | 문구 | 조치 버튼 |
|---|---|---|---|
| **`아직아님`** | **가장 약하게.** 회색, 테두리 없음 | "아직 시기가 아님" | **없음** |
| `하는중` | 차분한 초록 | "채워짐" | 없음 |
| `연결필요` | 앰버 | "목표를 겨냥한 활동 없음" | 활동 연결 |
| **`비어있음`** | 앰버 + 테두리 | "비어 있음" | 활동 추가 |
| `기준밖` | **파랑 (경고 아님)** | "목표 없이 하는 중" | 자체 기준 세우기 |

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-20** | **`아직아님` 는 조치 버튼을 띄우지 않는다.** 시각적으로 가장 약하다 | **C-6.** 아직 시기가 아닌 것은 빠뜨린 것이 아니다 |
| **INV-UI-21** | **`기준밖` 에 경고색을 쓰지 않는다** | 나쁜 상태가 아니다. "정리가 안 됐을 뿐"이다 |
| **INV-UI-22** | 커버리지를 **점수·퍼센트·진행바로 집계하지 않는다** | OOS-6 (성적화 금지). "5개 중 3개 완료"는 성적표다 |

## 3-B. 펫 (오늘 화면 상단) — 벌 없는 돌봄

> 사용자 아이디어: 완료할 때마다 **돌봄 버튼**(먹이/쓰다듬기/놀아주기)이 열리고,
> 아이가 눌러 펫을 돌보면 펫이 자란다. 밥 못 줘서 굶는 버전이 **아니다.**

| ID | 불변식 | 근거 |
|---|---|---|
| **INV-UI-41** | **펫은 안 돌봤다고 작아지거나 슬퍼지지 않는다.** 굶는·아픈·우는 표현 금지 | **벌 없음.** streak 철학. C-6 를 아이에게도 적용 |

| **INV-UI-43** | 완료 1개 → 토큰 1개. 돌봄 1회 → 토큰 1개 소모 (`performCare`) | 사용자 결정 |

## 6. 검증 방법 — 무엇이 자동이고 무엇이 수동인가

**정직하게 갈라둔다.** 전부 자동화되는 척하면 X-3 을 놓친다.

### 자동 (컴포넌트 테스트)

| 계약 | 검증 |
|---|---|
| INV-UI-00 / 11 | 컴포넌트 소스가 `nature ===` 로 직접 비교하지 않는다 (아키텍처 테스트) |
| INV-UI-05 | 할 일 없는 영역의 제목이 렌더되지 않는다 |
| INV-UI-06 / 07 | 체크 클릭 1회 → 상태 변경. 다이얼로그·입력 필드가 나타나지 않는다 |
| INV-UI-09 | `주N회` 활동에 진행 텍스트가 있다 |
| INV-UI-13 / 22 | 화면에 미완료 카운터·퍼센트 문자열이 없다 |
| INV-UI-14 | 영역 화면에 7개 영역이 모두 렌더된다 |
| INV-UI-16 | `자체` 배지와 `공교육` 배지의 클래스가 다르다 |
| INV-UI-18 | 오프셋 상향 시 경고와 신호가 렌더되고, 건너뛰기 버튼이 없다 |
| INV-UI-20 | `아직아님` 영역에 조치 버튼이 없다 |
| INV-UI-24 / 26 | 폼에 `nature` 입력과 알림 관련 컨트롤이 없다 |
| INV-UI-29 | 상태 요소에 텍스트 라벨이 함께 있다 |

### 수동 (실제 화면을 보고 확인)

| 계약 | 확인 방법 |
|---|---|
| **INV-UI-12** | 경고색이 빨강처럼 보이는가 |
| **INV-UI-21** | `기준밖` 가 "잘못됐다"로 읽히는가 |
| **X-2** (3초) | 앱 열고 체크까지 실제로 재본다 |
| **X-3** (죄책감) | **영어를 3일 빼먹은 상태의 화면을 보고, 기분이 나쁜가** |
| INV-UI-28 | 실제 폰에서 한 손으로 조작되는가 |

> **X-3 검증이 이 제품의 진짜 시험이다.**
> 기능이 다 맞아도 화면이 사람을 찌르면 2주 만에 안 열게 된다 (X-1).
> 배포 후 첫 주에 **일부러 며칠 빼먹은 상태로 화면을 열어보고** 판단할 것.

## 7. 아직 정하지 않은 것

- 구체적 색 토큰 값 (팔레트는 구현 시 확정)
- 다크 모드 지원 여부
- `연결필요` 라는 라벨이 화면에서 압박적인지 (사용 후 재검토)
- 오프라인 동작 범위 — INV-UI-32 의 "재시도" 구체 정책
