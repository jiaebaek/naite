### F2 — 활동 등록·관리

이제 활동이 코드 고정이 아니라 **사용자가 등록·수정**한다. 새 활동 폼은 이름·영역·주기만 필수(C-3),
겨냥할 목표는 칩으로 탭(생략 가능). **성격(nature)을 고르는 입력은 없다** — 겨냥 목표에서 자동 파생(INV-UI-24).
삭제는 **끄기(비활성화)** 로만 — 지난 기록이 고아가 되지 않게(INV-UI-27). 등록 즉시 저장된다.

### 펫 — 벌 없는 돌봄

완료 1개 → 돌봄 토큰 1개 → 먹이/쓰다듬기/놀아주기 1회 → 누적 돌봄으로 펫 성장(🥚→🐣→🐥→🐤→🐔).
**안 돌봤다고 굶거나 슬퍼지지 않는다** (INV-PET-02 · INV-UI-41) — streak 철학을 아이에게도 적용.
"밥 못 줘서 굶는" 버전을 의도적으로 배제했다: 아이에게 죄책감을 쓰는 건 엄마에게 안 쓰기로 한 것과 같은 것이다.

## 실행

**이 PC에서만:**
```powershell
. .\env.ps1
npm run dev
```
→ `http://localhost:5173`

**폰에서도 (같은 Wi-Fi):**
```powershell
. .\env.ps1
npm run dev:lan
```
→ 폰 브라우저에서 **`http://192.168.219.105:5173`**
(첫 실행 때 Windows 방화벽이 물으면 "허용". PC가 켜져 있고 서버가 떠 있어야 폰에서 열린다.)

- 모바일 폭으로 중앙 정렬된다. 저장은 브라우저별 localStorage — **폰에서 넣은 건 폰에만** 남는다.
- 홈 화면에 추가하면 앱처럼 쓸 수 있다 (아직 PWA 오프라인 캐시는 없음).
- 회사↔집·폰↔PC 동기화는 `.env.local` 에 Supabase 키를 넣으면 켜진다 (`src/boundary/store/supabase.ts` 상단 주석).

### 아키텍처 테스트가 지키는 것

단위 테스트로 증명하기 어려운 계약이 있다.
**"아빠에게 요구하지 않는다"(OOS-1 / INV-ACT-05)는 기능의 부재**라서 단언할 값이 없다.
그래서 `tests/architecture.test.ts` 는 **그런 코드가 존재하지 않음**을 검사한다.

| 검사 | 지키는 것 |
|---|---|
| 도메인이 react·supabase·`node:*` 를 import 하지 않는다 | ECB 단방향 (Boundary → Entity) |
| 도메인이 `fetch`·`localStorage` 를 쓰지 않는다 | Entity 순수성 |
| notify·assign·remind·alert·push 를 export 하지 않는다 | **OOS-1 / X-4** |
| `owner` 로 조건 분기하지 않는다 | **"아빠면 ~한다" 가 생기는 순간 실패** |
| `Activity` 에 `nature` 필드가 없다 | INV-ACT-02 |
| `coverage.ts` 코드가 `Completion` 을 다루지 않는다 | INV-COV-05 (C-6) |

## 문서 역할 — 같은 사실을 두 번 적지 않는다

| 무엇 | 어디 | 보호 |
|---|---|---|
| **원문** (사실) | `docs/원문/` | 교육과정 원문 그대로. 요약·의역 금지 |
| **데이터** (앱이 쓰는 것) | `src/domain/standards/child2021.ts` | 원문 충실성 테스트 |
| **해설** (사람이 읽는 것) | `docs/04` | **기준을 옮겨 적지 않는다.** 링크만 |
| **계약·PRD** | `docs/05~07` | 정합성 테스트 (`tests/docs/`) |

04 문서가 코드보다 뒤처진 적이 있다 — 영역이 4개 → 7개로, 용어가 `초과 목표` → `추가` 로
바뀌었는데 문서는 그대로였다. **마크다운은 타입 검사를 받지 않기 때문**이다.
`tests/docs/consistency.test.ts` 가 코드의 상수(`DOMAINS`·`NATURES`·`COVERAGES`·`ERROR_CODES`)가
문서에 실제로 존재하는지, **폐기된 용어가 본문에 남아 있지 않은지** 확인한다.

### P-6 실증 — 실제 데이터로 판정한 현재 상태

| 영역 | 상태 | 근거 |
|---|---|---|
| 국어 · 수학 · 영어 | `하는중` | 등록된 활동이 지금 목표를 겨냥 |
| **예체능 · 건강·안전** | `하는중` | 학원 **등원 자체**가 영역을 덮음 (아이마음아트·유아체육, INV-ACAD-06) |
| **사회·인성** | **`비어있음`** | 04 문서 §5가 지적한 그 지점 |
| **과학·탐구** | **`비어있음`** | Domain 5개 시절엔 존재조차 않던 영역 |

> 위는 시드 데이터 기준이다. 실제 앱에서는 **사용자가 등록하는 대로** 판정된다.
> `아직아님`(아직 시기 아님)과 `비어있음`(시기인데 비었음)은 다르다 — 전자는 조치가 필요 없다.
> 영역 탭은 이 중 **`비어있음`(갭)을 앞세워** 보여준다 — 됨은 관리 탭에서.

## 개발 방식

- **DbC + TDD**. 계약 ID 1개 = 테스트 1개 이상. **계약에 없는 동작은 구현하지 않는다.**
- **ECB 두 트랙**
  - **Entity 트랙** — `src/domain/`. 순수 함수. I/O 없음. Control(유스케이스) 포함. TDD의 90%가 여기
  - **Boundary 트랙** — `src/boundary/`. UI · 저장소 · Supabase
- **의존 방향: Boundary → Entity 단방향.** `domain/` 은 React·Supabase를 import하지 않는다

## 가장 현실적인 리스크 (U-8)

노션이 실패한 이유가 복잡도인데, **직접 만들면 복잡해도 쓸 수 있어서 제약을 스스로 어기기 쉽다.**
기능을 추가할 때마다 묻는다 — **"이게 냉장고 종이보다 쉬운가?"**

성공 지표는 기능 개수가 아니라 **2주 중 10일 사용**이다.
